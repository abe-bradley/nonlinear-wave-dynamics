SHARED COLORMAP INTERFACE

Run init_dir to add the main code tree to the MATLAB path. All maintained
plotting code obtains named palette colors through ot_colormap:

    colors = ot_colormap("guppy",256);
    colormap(ax,ot_colormap("parula",256));
    colors = sqrt(ot_colormap("Purples",256));
    colors = flipud(ot_colormap("thermal-2",256));

The default requested length is 256. The output is an N-by-3 RGB array.
N must be a nonnegative integer; N=0 returns an empty 0-by-3 array. A palette
name or original numeric ID is required; there is no zero-argument palette.
Standard MATLAB plotting functions still apply the returned colors to axes,
lines, markers, patches, or other graphics objects. Existing custom RGB
arrays and plot-specific transformations can be used directly.

An optional second output describes the selected palette and its source,
license, and MATLAB release:

    [colors,info] = ot_colormap("guppy",256);

LOOKUP AND ROUTING

Names are matched against the maintained catalog. Registered MATLAB-native
names use installed MATLAB functions; external names use the reviewed table
file. Native maps unavailable in the current MATLAB release produce an
availability error. A different palette is not substituted silently.

The native registry includes parula, turbo, hsv, hot, cool, spring, summer,
autumn, winter, gray, bone, copper, pink, jet, lines, colorcube, prism, flag,
white, abyss, sky, and nebula. A registered name does not guarantee that its
MATLAB function is available in every supported release.

Original slanCM numeric IDs remain aliases for their original names:

    colors = ot_colormap(6,256);    % parula, generated by MATLAB

The catalog contains 199 retained original entries and five additional
MATLAB-native names, for 204 names in total. Its 182 external entries have
stored RGB tables. The five additional native names have no original numeric
ID. The remaining IDs are not renumbered. Original ID 192 (colorblind) and
that palette's data are absent. Requesting it produces UnknownPaletteID. There is
no list-query overload; inspect data/palette_catalog.json for inventory,
sources, credits, licenses, and routing metadata.

DATA AND REPRODUCIBILITY

The files in data are resolved relative to ot_colormap's location. They
do not depend on the current directory or the checkout folder's name.

data/external_palettes.mat contains reviewed external 256-row tables.
Native table payloads and colorblind are omitted. External values keep the
precision in the original collection; requested lengths are obtained using
the existing linear-interpolation convention. MATLAB-native requests use
the installed function at the requested N. They may differ from the old
slanCM snapshot or from another MATLAB release. For reproducible native
colors, record the MATLAB release along with the palette name and length.

The original complete slanCM library is a local archive under
Packages/slanCM_original. Main-directory initialization excludes Packages and
.temp scratch exports, which can contain stale copies of plotting functions;
the new provider does not load or fall back to that archive. The archive and
.temp audit files should not be included in the intended public release.

LICENSING

External palette designs remain third-party material. The accompanying
THIRD_PARTY_NOTICES.txt identifies collection and original-designer credits,
source links, license texts, aliases, and processing. LICENSES
contains the preserved source terms. Include these materials whenever the
external table file is redistributed. An independently written lookup
function does not change the licenses applying to its external data.

EXPLICIT COLORBREWER SAMPLING

    colors = ot_colormap("Set1",3,"Sampling","colorbrewer");
    colors = ot_colormap("Purples",256,"Sampling","colorbrewer");
    [colors,info] = ot_colormap("RdBu",11,"Sampling","colorbrewer");

Two-argument calls keep the existing palette sampling. The explicit option
"Sampling","default" also selects the existing behavior. Options require
an explicit N. Names and option values are case insensitive. Original numeric
IDs also work when they resolve to one of the 35 official scheme names.
Other palettes reject ColorBrewer sampling instead of silently substituting.

The new data file data/colorbrewer_schemes.json contains the original integer
RGB selections for all 35 schemes and 265 designed color counts, taken directly
from Axis Maps' official ColorBrewer source. It is independent of the removed
BrewerMap package. Source URL, pinned commit, source SHA-256, authors, and
extraction details are recorded in that JSON file.

Sampling rules:
- At a designed count, return exactly the official selection, divided by 255.
- For larger sequential palettes, use shape-preserving cubic (pchip)
  interpolation of the largest designed selection.
- For larger diverging palettes, interpolate the two arms separately,
  retaining the neutral center for odd output lengths.
- For excess qualitative colors, cycle the largest designed set; do not blend.
- N=0 returns an empty 0-by-3 array.
- ColorBrewer defines no one- or two-color selections. For sequential/diverging
  palettes, N=1 uses the middle of the smallest designed selection and N=2 its
  endpoints. Qualitative N=1/2 uses the leading colors of the largest set.
  These small-count rules are our documented extensions, not official designs.

The optional metadata output identifies provider=colorbrewer, the source
scheme, type, license, URL, and sampling method. This is independent sampling,
not a promise of exact compatibility with every BrewerMap extension. In the
265 designed selections compared with the old local package, Oranges at N=4
was the only difference (at most one 8-bit level per RGB channel). Our explicit
mode follows the pinned official data. Existing default outputs are unchanged.
